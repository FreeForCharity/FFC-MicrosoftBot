# GitHub Copilot Instructions for FFC-MicrosoftBot

## Project Overview

This repository contains a Microsoft Bot Framework v4 QnA Maker bot for Free For Charity (FFC), a non-profit organization. The bot is designed to provide FAQ-style assistance to users across FFC's websites including:

- Main site: https://freeforcharity.org
- Free hosting platform: https://ffchosting.org  
- Client management platform (WHMCS): https://ffchosting.org/hub

## Technology Stack

- **Framework**: Microsoft Bot Framework v4
- **Language**: C# 
- **Target Framework**: .NET Core 2.1
- **Cognitive Service**: Azure QnA Maker
- **Web Framework**: ASP.NET Core 2.1
- **State Management**: In-Memory Storage (for development/testing)
- **Hosting**: Azure Bot Service

## Coding Guidelines

### Bot Framework Patterns

1. **Activity Handlers**: Follow the standard Bot Framework pattern of overriding `OnMessageActivityAsync` and `OnMembersAddedAsync` in the main bot class.

2. **Dialog Management**: Use the Dialog system for complex conversation flows:
   - Extend `ComponentDialog` for reusable dialogs
   - Use `DialogContext` for managing dialog state
   - Implement proper dialog lifecycle methods

3. **State Management**: 
   - Use `ConversationState` for temporary conversation data
   - Use `UserState` for persistent user data across conversations
   - Always call `SaveChangesAsync()` after each turn

4. **QnA Maker Integration**:
   - Use `QnAMaker` class for querying the knowledge base
   - Implement proper error handling for QnA service calls
   - Support multi-turn conversations and active learning

### Code Style

1. **Namespace Convention**: Use `Microsoft.BotBuilderSamples` as the root namespace
2. **Dependency Injection**: Register all services in `Startup.cs` using appropriate lifetimes
3. **Async/Await**: Always use async methods for Bot Framework operations
4. **Error Handling**: Implement proper exception handling and logging
5. **Configuration**: Use `appsettings.json` for configuration values, never hardcode secrets

### Key Classes and Methods

- **QnABot<T>**: Main bot class that handles incoming activities
- **RootDialog**: Primary dialog that orchestrates conversation flow
- **QnAMakerBaseDialog**: Base class for QnA Maker interactions
- **BotServices**: Service class that manages QnA Maker client

## Configuration

The bot requires the following configuration values in `appsettings.json`:

```json
{
  "MicrosoftAppId": "your-app-id",
  "MicrosoftAppPassword": "your-app-password", 
  "QnAKnowledgebaseId": "your-kb-id",
  "QnAAuthKey": "your-qna-key",
  "QnAEndpointHostName": "your-qna-endpoint"
}
```

## Development Guidelines

1. **Testing**: Use Bot Framework Emulator for local testing at `http://localhost:3999/api/messages`

2. **Deployment**: The project includes Azure deployment scripts:
   - `build.cmd` - Build the project
   - `deploy.cmd` - Deploy to Azure
   - `publish.cmd` - Publish the application

3. **QnA Maker Setup**: Follow Microsoft documentation for creating and configuring QnA Maker knowledge bases with multi-turn and active learning features.

4. **Non-Profit Context**: Remember this bot serves a non-profit organization focused on providing free services to charities. Keep this mission in mind when suggesting features or improvements.

## Common Tasks

### Adding New Dialogs
- Extend `ComponentDialog` or `QnAMakerBaseDialog`
- Register in `Startup.cs` dependency injection
- Add to dialog stack in `RootDialog.cs`

### Modifying QnA Responses
- Update knowledge base in QnA Maker portal
- Redeploy knowledge base
- Test with Bot Framework Emulator

### Adding New Bot Responses
- Use `MessageFactory.Text()` for simple text responses
- Use `MessageFactory.Attachment()` for rich responses
- Implement proper turn handling in dialog classes

## Security Notes

- Never commit secrets to source control
- Use Azure Key Vault for production secrets
- Implement proper authentication for production deployment
- Follow Microsoft security best practices for bot development
